# 자동화 전략

## 저장 규칙
이 폴더에 전체 검사 실행기, 실행 명령, 결과 요약/소스 해시를 저장한다. 실 테스트 코드는 backend/tests, frontend/src/**/tests, frontend/e2e. 사용자의 '자동화테스트 docs/automation 저장'은 이 폴더의 통합 실행기로 실행·결과를 재현하는 구조로 적용한다.

## 게이트
1. backend: ruff check/format, pytest 단위/API 계약.
2. frontend: TypeScript typecheck, ESLint MVVM 경계, Vitest/Testing Library.
3. build: Vite production build, Python compile.
4. integration: PostgreSQL migrations/RLS, Redis 작업 복구, HTTP mock/SMTP 계약.
5. UI: Playwright Chromium, 한국어 label과 키보드로 사용자 여정.
6. 문서: OpenAPI 동기화, PDF 한국어 텍스트/페이지 렌더 확인.

## 증거
실행 시작/종료 UTC, 정확한 명령/exit code, source hash, dependency lock hash를 report.json과 검증결과.md에 저장. 실행 안 한 검사는 NOT_RUN으로 구분. skip을 pass로 집계하지 않는다. 실패한 필수 게이트는 배포 불가. 실제 Zoom/Groq/카카오 발송은 test suite에서 금지하고 mock transport로 계약 검사.

## 개발과 운영
개발 명시적 fake mode는 UI 표시. 운영 기본키/fake/SQLite 금지. 실제 API 키는 환경변수 또는 secret store, 테스트/문서/저장소에 값 기입 금지. 유료 업그레이드·배포·commit/push는 사용자 별도 지시 필요.

## 테스트 데이터
2회사, 관리자/일반 직원, 동명이인, 초대 미수락, 비활성 수신자, 429/timeout, 역순 Zoom 웹훅, 긴 한글 녹취, 잘못된 근거. 고정 테스트 시간과 로컬 provider를 사용한다. 실제 개인정보나 고객 녹음은 fixture로 저장하지 않는다.

## CI
Linux Python/Node 버전 고정, PG/Redis service, 의존성 lock 기반 설치. 단위→통합→build→E2E. 결과물은 report와 Playwright trace/PDF 미리보기. 항상 재시도로 flaky를 감추지 않는다. 환경 부재 시 코드 검증은 계속하고 해당 게이트를 미실행으로 명시한다.
