# 단위 테스트 설계

## 서버 pytest
- U01 parse_transcript: VTT/SRT timestamp·UTF-8·빈 값·위장 파일·크기 제한.
- U02 summary schema: 없는 근거 ID/기한 timezone/빈 action/추측 담당자 거부.
- U03 identity: 비밀번호 해시·세션 토큰 해시·만료·CSRF·일회용 토큰 재사용 거부.
- U04 policy: 일반 직원 초안/원문 차단, 버전/수신자 변경 후 승인 무효, 마지막 관리자 보호.
- U05 job: claim race, fence 불일치 결과 거부, 지수 backoff와 재시도 상한.
- U06 delivery: 동일 버전 중복 생성 방지, timeout unknown, 미연결 카카오 skipped, 권한 철회.
- U07 crypto/storage: 토큰 암호화 roundtrip, path traversal/SSRF/HTTP redirect 거부.

## React Vitest
- F01 model: 상태 label, 자동 발송 가능 조건, 비정상 API 값 처리.
- F02 VM: 로딩→데이터, 오류→재시도, 저장 중 중복 클릭 차단.
- F03 VM: 회사 전환 후 늦은 응답이 이전 회사 데이터를 표시하지 않음.
- F04 VM: 수신자 변경·버전 충돌 시 승인 재요청.
- F05 View: label 연결, loading/empty/error, 키보드 입력·버튼 비활성.

Repository 주입으로 네트워크 없는 hook 테스트. DOM 검사와 업무 규칙 검사는 분리. 내부 구현 호출 횟수만 검사하는 테스트 대신 결과·외부 효과를 검사한다. 난수/시간은 고정 fixture로 제어한다.

## 실행
backend: python -m pytest tests/unit -q.
frontend: npm test -- --run.
TDD: 테스트 작성→의도한 실패 확인→최소 구현→통과 확인. 실패 근거와 최종 결과는 docs/automation에 기록한다.
