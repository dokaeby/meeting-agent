# 통합 테스트 설계

## API+DB
I01 A회사 관리자/B회사 관리자/일반 직원 fixture로 모든 조회·수정·PDF 회사 침범 404.
I02 session/CSRF, 가입 중복, 이메일 확인 전 연동 차단, 초대 토큰 재사용·이메일 불일치.
I03 회의→수신자→녹취→job→문서→승인→발송 전체 흐름과 감사 기록.
I04 버전 변경 또는 수신자 변경 후 기존 승인 사용 409.

## 실제 PostgreSQL
I05 Alembic upgrade head→테이블/복합FK/unique/인덱스 확인.
I06 runtime role은 owner/superuser/bypassrls 아님. org context 미설정 조회 0행, 교차회사 INSERT 거부.
I07 트랜잭션 종료 후 context 유출 없음. 연결 풀 재사용 시 재설정.
I08 동시 job claim/승인·수신자 변경 경쟁을 두 연결로 재현.
SQLite 통과는 이 항목의 성공 증거가 아님.

## worker/Redis
I09 DB commit 후 broker 전송 실패→다음 dispatcher가 작업 복구.
I10 작업자 kill→리스 만료·fence 갱신→낡은 작업자 결과 거부.
I11 발송 접수 후 DB 기록 전 중단→unknown, 자동 중복 전송 없음.

## 외부 계약(mock HTTP)
I12 Zoom challenge, HMAC timestamp·서명, 중복·역순 완료 이벤트, 다른 tenant payload.
I13 OAuth state 일회용/만료/연결 해제, refresh 만료·동시 갱신.
I14 Groq STT·chat JSON 계약, 429/5xx/비정상 JSON/없는 근거 ID.
I15 SMTP MIME 한국어·PDF 첨부/카카오 self 메시지·토큰 철회·timeout.

## 파일/PDF
I16 경로 탈출/위장 MIME/허용 외 다운로드/대용량/긴 녹취 제한.
I17 한국어 PDF 텍스트와 페이지 렌더, 권한 철회 후 다운로드 거부.

실행: python -m pytest tests/integration -q. PG_URL이 있어야 하는 검사는 환경 부재를 skip으로 명시하고 보고서에 NOT_RUN. CI에서는 PG_URL을 필수 설정해 skip 방지. 모든 네트워크 provider는 test fixture로 대체하며 실제 발송 없음.
